# Route delivery by destination capability

VoxKey selects its Delivery Route from observed Destination Capabilities rather than maintaining broad Slack, Terminal, Electron, Browser, and standard-app injector classes. Web-specific Accessibility roles and attributes select guarded paste directly; native single-line controls may use direct insertion, while multiline controls use paste. An explicit unsupported/not-implemented rejection is remembered only for that application process and selects guarded paste thereafter. An accepted or ambiguously applied write is observed once and never triggers an automatic second write. Application identity remains part of the captured evidence, but named Compatibility Adapters are added only for reproduced exceptions and must have focused fixtures and tests. This avoids encoding unreliable assumptions about named applications while still allowing precise workarounds where capability detection is insufficient.
