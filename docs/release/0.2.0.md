# VoxKey 0.2.0

VoxKey 0.2.0 improves capture feedback, recovery, and Settings responsiveness, and
refreshes the public project page and contributor documentation.

## Changes

- Releases now use SemVer tags such as `v0.2.0`, without a beta suffix. The
  internal Sparkle build counter remains independent and increases with each release.
- **Listening** now uses a dark green pill with a lime input waveform and a
  keycap for your configured trigger. Toggle instructions and capture-limit
  warnings remain visible in both light and dark appearances.
- **Recover Dictation…** appears only when a result needs recovery and dictation
  is idle. Confirmed delivery clears the retained result and closes its panel.
  Unconfirmed delivery remains recoverable with the existing duplicate check.
- Settings avoids repeating unchanged readiness updates or refreshing hidden
  controls. Returning from System Settings refreshes Launch at Login status.
- Bursts of focus notifications are combined within a 30 ms window. Starting a
  dictation still resolves the current destination immediately.
- **Send Feedback…** in Settings opens the project's GitHub issue templates.
- The microphone permission explanation now covers both hold and toggle modes.
- The public page is shorter, explains installation, links to releases, and
  states that VoxKey is local, free forever, and open source.
- Documentation distinguishes current behavior from planned features.
  Exploratory archives and company-specific examples have been removed; model
  reproduction tools and the regression corpus remain available.

## Installation and updates

Download the DMG, open it, and drag VoxKey into Applications. Quit any running
VoxKey instance before replacing it. The menu should show **VoxKey 0.2.0**.
Existing preferences, vocabulary, and downloaded models are preserved.
Existing users can also use **Check for Updates…** after the release reaches the
signed update feed.

Optional grammar correction uses the same separately downloaded model as Beta 5.
It remains off by default, can change words, and has noncommercial-only model
terms separate from VoxKey's MIT source license.

## Validation and limits

Automated checks cover recovery retention and clearing, menu visibility,
readiness refresh, focus-event handling, and capture-overlay layout. The native
64-case grammar corpus verifies expected token IDs and corrected output against
the installed model. The public page is checked at mobile and desktop widths.

Physical microphone-to-editor behavior, launch at login after signing out,
upgrade/restart from an earlier beta, and the full third-party editor matrix
still require manual acceptance. Automated and controlled fixtures do not
establish compatibility with every editor or Mac configuration.
